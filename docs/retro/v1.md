# GlobaLens v1: what the repository contained

**Status: draft for the owner to correct.** Drafted on 15 November 2026 from [`docs/3.0/v1-audit.md`](../3.0/v1-audit.md) and from the files at commit `26e15f4`, which the tag `v1-hackathon` names. v1 is no longer on `main`; every path below is a path at that tag.

How to check a line: each statement cites a file and line at the tag, a commit, or the audit. To read a cited file, run `git show v1-hackathon:<path>`. Where the repository cannot answer a question, this note says so and leaves it for the owner (see the last section).

## What v1 was

- 13 commits, dated 11 to 16 June 2025 (`git log v1-hackathon`). Their messages include "Full Stack", "Populate", "FInal" (twice), "GCP", "GCP 2", "Push" and "Readme".
- The audit counts about 1,730 lines (audit, line 3).
- Four parts:
  - `Frontend/globe/`: a single-page Vite and React app with a `react-globe.gl` globe (`package.json`).
  - `backend/data_fetch/app.py`: one Flask file, 169 lines, with two routes over MongoDB Atlas (lines 79 and 126).
  - `process-articles/process_articles.py`: a 389-line script that fetched and parsed articles.
  - `populateDB/populate_db.py`: a 74-line seeder.
- No test file, CI workflow, Dockerfile, infrastructure code or `LICENSE` file is in the tree at the tag (`git ls-tree -r v1-hackathon`).

## What the seeder did

`populateDB/populate_db.py`:

- It targets database `news_database`, collection `temp`, with `NUM_DOCUMENTS = 300000` (lines 17 to 19).
- It drops the collection (line 49), then inserts 300,000 generated documents in batches of 1,000 (lines 55 to 57).
- Every field is made up (lines 24 to 39): a Faker URL, a Faker sentence as `Title`, Faker paragraphs as `text` and `summary`, a latitude and longitude drawn uniformly at random, and a `summary_embedding` of 768 random numbers between -1 and 1 (line 38).

How that meets the rest of v1:

- The API reads the same collection: `DB_NAME = "news_database"`, `COLLECTION_NAME = "temp"` (`app.py`, lines 27 and 28).
- The article pipeline writes to a different collection, `articles` (`process_articles.py`, line 231). Nothing in the repository copies `articles` into `temp`.
- So the seeder is the only code in the repository that writes the collection the API serves.
- `/api/vector_search` embeds the query with the sentence model `all-mpnet-base-v2` (`app.py`, line 43) and searches the field `summary_embedding` (line 145). In seeded documents that field holds random numbers, not an embedding of any text.
- The seeder writes the field `Title`; the API returns `title` (`app.py`, line 71); the frontend falls back to the source URL when `title` is missing (`Frontend/globe/src/App.tsx`, line 16).

What the repository cannot show: what the database held when v1 was demonstrated. The audit calls synthetic data "very likely" (audit, lines 53 to 55). That is an inference, not a record.

## Other things the code did

- **Fetching articles.** The pipeline requested article pages with a fixed Chrome-on-Windows `User-Agent` header (`process_articles.py`, line 36), ten at a time (line 33), and stored each article's full text (line 51). The word "robots" does not appear in the file.
- **No deduplication.** Records go in with `insert_many` (line 348); the file has no upsert.
- **A hardcoded API address.** `Frontend/globe/firebase.json` rewrites `/api/**` to a Cloud Run service named `globalens-backend` (lines 9 to 16), but every request goes to `http://127.0.0.1:5001` (`App.tsx`, lines 10 and 43).
- **One payload.** The frontend asks for up to 2,000 documents in one response (`App.tsx`, lines 11 and 68; `app.py`, lines 29 and 89) and does not ask again on a timer.

## What 3.0 keeps

The plan keeps the name, the tagline, GDELT, the dark look and the Lens gesture (`docs/3.0/master-plan.md`, §2). In v1 the Lens is a fixed circle at the centre of the screen (`CircleSelector.tsx`); points whose screen position falls inside it (`GlobeScene.tsx`, lines 33 to 55) are listed, ten at most, under "News in View" (`NewsListPanel.tsx`, lines 14 and 25).

## Why this note exists

The plan names two things from v1 that 3.0 is built not to repeat: a seeder that replaced the served data with generated data, and a README that described a system the repository did not contain. The metrics ledger, the generated status table and the labelled numbers are there for that reason (`docs/3.0/master-plan.md`, §2).
